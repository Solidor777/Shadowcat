# Documentation-Generation Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive TypeDoc and rustdoc to zero warnings, make warnings fail CI, fold documentation regeneration into the full build, and make `dist-docs/index.html` open by double-click.

**Architecture:** Four independent workstreams that converge on one hardened pipeline. Warning elimination comes first (rustdoc, then TypeDoc), because the gates in workstream three must only be tightened onto an already-clean tree. Build restructuring and the relative-path rewrite follow, then the codebase skills gain pointers into the generated output.

**Tech Stack:** TypeDoc 0.28, rustdoc, VitePress 1.6, Zod, Vitest, pnpm workspaces, GitHub Actions.

## Global Constraints

- Cross-platform: `node:path` / `std::path` only. No hardcoded separators, no shell builtins in scripts, no assumed binary suffix.
- No lint suppressions. `#[allow]`, `#[expect]`, `eslint-disable`, `@ts-ignore`, `@ts-nocheck` are forbidden without per-instance owner sign-off.
- Comments cite symbols, never file names or line numbers.
- Comments must not reference milestones, tasks, dates, plans, or history. Enforced by `pnpm lint:comments`.
- No ratchets, only gates. Nothing is grandfathered.
- Never delete files with `rm` / `Remove-Item`; use `trash` with a relative path.
- Commit with explicit paths: `git commit -m "..." -- <paths>`.
- `dist/` must be built before any `cargo` build or `cargo doc` — `rust-embed` validates it at compile time.
- ts-rs bindings under `src/types/generated/` are generated by `cargo test`. Never hand-edit them.

## Verification Helpers

Used throughout. Both are read-only.

```bash
# Distinct TypeDoc warning lines (strips ANSI, which otherwise breaks matching)
pnpm docs:api:ts 2>&1 | sed -E 's/\x1b\[[0-9;]*m//g' | grep -c '^\[warning\]'

# Whether a specific symbol still warns
pnpm docs:api:ts 2>&1 | sed -E 's/\x1b\[[0-9;]*m//g' | grep '^\[warning\] ServerMsgSchema'
```

Baseline at plan time: **TypeDoc 0 errors / 1299 warnings**, **rustdoc 11 warnings**.

Warning counts fall in jumps that do not track effort, because one undocumented leaf is reported once per path that reaches it. Verify by *symbol absence*, and treat the count only as a monotonic check that it went down.

## Task 3: Name the wire.ts leaf schema types

**Files:**
- Modify: `src/client/core/src/wire.ts`

**Interfaces:**
- Consumes: nothing.
- Produces: `WireFieldChange`, `WireOperation`, `WireCommand`, `WireSearchHit`, `WireCapabilityRequirement` become hand-written documented types instead of `z.infer` aliases. Their names and members are unchanged, so no consumer needs editing.

The schemas nest: `ServerMsgSchema` contains `CommandSchema`, which contains `OperationSchema`, which contains `FieldChangeSchema`. TypeDoc expands the whole chain anonymously, so a leaf documented late is documented twice. **Work leaf-first.** Task 4 depends on this task completing.

### The pattern

Today, types derive from schemas, which is why a schema cannot be annotated with its own type — it is circular:

```ts
export const FieldChangeSchema = z.object({ /* ... */ });
export type WireFieldChange = z.infer<typeof FieldChangeSchema>;   // circular if annotated
```

Invert it. Hand-write the type with a doc comment per member, then annotate the schema:

```ts
/** A single field-level change within an `Operation`. */
export type WireFieldChange = {
  /** JSON-pointer-style path to the field being changed. */
  path: string;
  /** The value before the change, for conflict detection and rollback. */
  old: unknown;
  /** The value after the change. Ignored when `remove` is true. */
  new: unknown;
  /** When true, REMOVE the object key at `path` (genuine absence) instead of
   * setting `new`. Omitted on the wire when false (mirrors the server's
   * `#[serde(skip_serializing_if)]`). */
  remove?: boolean;
};

/** Validator for a single field change carried by an `Operation`. */
export const FieldChangeSchema: z.ZodType<WireFieldChange> = z.object({
  path: z.string(),
  old: z.unknown(),
  new: z.unknown(),
  remove: z.boolean().optional(),
});
```

Three properties of this pattern matter:

1. The compiler enforces agreement. If the schema stops producing exactly `WireFieldChange`, the annotation fails to build. Schema and type are not a forked decision.
2. Existing comments inside the `z.object` move onto the type members, where TypeDoc can see them. Do not leave a duplicate behind — a stale copy is a maintenance trap.
3. `z.ZodType<T>` erases the schema surface (`.shape`, `.extend()`). A repo-wide search found zero call sites using it, so this is safe; if one is introduced later the build fails loudly.

```js
/** The enumerated documentation exemptions in effect for a TypeDoc config. */
export function reportDocExemptions(config) {
  const names = config.intentionallyNotDocumented ?? [];
```

```js
/** Rewrite one root-absolute local link to a path relative to a page at `depth`
 * directories below the site root. Scheme-prefixed, protocol-relative, fragment-only
 * and already-relative links pass through untouched.
 * A directory target is expanded to its index.html: file:// does not resolve a bare
 * directory, unlike an HTTP server. */
export function toRelativeHref(link, depth) {
  if (SKIP_SCHEMES.test(link) || !link.startsWith("/")) return link;
  const hash = link.indexOf("#");
  const frag = hash === -1 ? "" : link.slice(hash);
  let path = hash === -1 ? link : link.slice(0, hash);
  if (path.endsWith("/")) path += "index.html";
  const prefix = depth === 0 ? "./" : "../".repeat(depth);
  return prefix + path.slice(1) + frag;
}
```

- [ ] **Step 5: Implement the file-walking rewrite**

```js
/** Rewrite root-absolute local refs in the given portal files to depth-relative
 * ones, so the assembled site resolves under file:// as well as over HTTP.
 * Returns the number of files changed. */
export function rewriteAbsolutePaths(rootDir, files) {
  let changed = 0;
  for (const file of files) {
    const depth = relative(rootDir, dirname(file)).split(sep).filter(Boolean).length;
    const before = readFileSync(file, "utf8");
    const after = file.endsWith(".css")
      ? before.replace(/url\(("|')?(\/[^"')]+)\1?\)/g, (m, q = "", p) => `url(${q}${toRelativeHref(p, depth)}${q})`)
      : before.replace(/(href|src)="([^"]+)"/g, (m, attr, link) => `${attr}="${toRelativeHref(link, depth)}"`);
    if (after !== before) {
      writeFileSync(file, after);
      changed += 1;
    }
  }
  return changed;
}
```

Add `relative`, `dirname` to the `node:path` import and `writeFileSync` to the `node:fs` import.

Do **not** rewrite absolute paths inside the VitePress runtime JavaScript. Over `file://` the browser refuses to load module scripts at all, so those paths are never dereferenced; over HTTP the runtime behaves exactly as today.
