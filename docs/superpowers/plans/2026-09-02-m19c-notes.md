# M19c · Notes — Implementation Plan

> **For agentic workers:** Execute task-by-task in order; each task's steps use checkbox
> (`- [ ]`) syntax. Written for a sonnet-class implementer with no conversation context —
> every path, symbol and test name below is exact; read the cited code before editing it.

**Goal:** `note` documents whose author markdown (`source`) is rendered **at ingress by the
server** into a sanitized `body: Vec<Segment>` through the chat sanitizer boundary — with
`[[doc:…]]`/`[[token:…]]` cross-references, `[[roll:…]]` (and inline `[[…]]`) buttons and
`[[asset:…]]` images — organized as a `parent_id` tree, private by default, readable by any
M20 sheet through ui-kit's `SegmentList`.

**Architecture:** `data::engine::note::NoteEngine` with a server-derived `body` produced in
`normalize_engine`'s `"note"` arm via `chat::body::compose_static` under the fixed
`NOTE_CONTENT_POLICY`; `check_note_parent` beside `check_asset_folder_parent`; core
`note-docs.ts` (`buildNoteDoc`, `parseNoteBody`).

**Tech stack:** Rust, ts-rs (regenerated), Vitest.

**Spec:** `docs/superpowers/specs/2026-09-02-m19-tables-notes-chat-media-design.md` — §2.2, §3.1,
§3.3, §3.5, §4, §6, §7, §8, §11 (C2–C4, N1–N8). Read it first.

**Prerequisite:** M19a and M19b merged to `main` (`chat::body`, `Segment::Image`,
`scan_body_capped`, ui-kit `SegmentList`, the `tables-notes` skill).

### Task 1: `chat::body::compose_static` + `NOTE_CONTENT_POLICY`

**Files:**
- Modify: `src/server/src/chat/body.rs`, `src/server/src/chat/body/tests.rs`,
  `src/server/src/chat/settings.rs` (`pub const NOTE_CONTENT_POLICY: ChatContentPolicy` —
  markdown on, html off, images on, hyperlinks on, emails off, `link_previews: Some(false)`;
  `ChatContentPolicy` is the `ChatSettingsEngine` alias — if its fields are `Option<bool>`
  construct the `Some` forms; if a `const` cannot be built, `pub fn note_content_policy() ->
  ChatContentPolicy`), `src/server/src/chat/mod.rs` (re-export).

**Interface:** `pub(crate) fn compose_static(body: &str, policy: &ChatContentPolicy, max_spans:
usize) -> Result<Vec<Segment>, RollError>` — synchronous: `scan_body_capped(body, max_spans)`;
`Text` → `sanitize(t, policy).segments` — `Sanitized.image_urls` is deliberately discarded: no
outbound fetch exists on the document-write path, so a markdown image in a note renders as its
alt text (the sanitizer already replaced the image event with it) and only `[[asset:…]]` spans
produce images; state this on `compose_static`'s doc comment;
`Inline(f)` → `validate_formula(f.trim(), ParseContext::default())` → `Segment::RollButton {
formula, label: None }`; `Button` → `RollButton`; `DocLink` → `DocLink`; `Image` →
`Segment::Image { asset_id, alt }` (no existence check — documented per spec §3.3; alt over
`MAX_IMAGE_ALT_CHARS` ⇒ `RollError::AltTooLong`).

- [ ] **Step 1:** failing tests — each chunk kind maps as above; `[[1d6]]` becomes a button, never
  a `RollEmbed`; a `t15`-style formula validates under the default context; malformed span errors
  propagate; the 65th span ⇒ `TooManyInline`; text is sanitized under the passed policy (assert
  markdown → `Html`, a raw `<b>` escaped, an `<img src>` never present, `<a href>` present).
- [ ] **Step 2:** implement. `cargo test -p shadowcat chat` PASS; clippy; fmt.
- [ ] **Step 3:** `git commit -m "feat(chat): static body composer for server-derived document bodies" -- src/server/src/chat/`
