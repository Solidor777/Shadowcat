## Task 1 — Vision-mode descriptor v2 (server + client mirrors)

- `data/engine/scene.rs` `VisionMode` gains `perceives: Perception` (`terrain` | `creatures`,
  serde camelCase, default `terrain`) and `requires_los: bool` (serde default `true`), ts-rs
  exported, every field documented (docs ratchet). `VisionModesEngine::seed` gains
  `tremorsense { name: "Tremorsense", perceives: Creatures, requires_los: false,
  default_range: 12, illumination_floor: "dark" (inert for creature senses), render_hint: None }`.
- Server resolved `VisionMode` (`scene/mod.rs`) carries the new fields through
  `resolved_vision_modes`; unknown/absent doc ⇒ seeds unchanged.
- Client: `SEED_VISION_MODES` mirror + `resolveVisionModes` pass-through + Zod drift-guard mirror +
  regenerated ts-rs bindings.

## Task 2 — `perceived` channel (server)

- New module `scene/senses.rs` (mod.rs growth discipline): creature-sense resolution.
  `SceneEcs::player_perceived_tokens(user, ctx, world_defaults) -> Vec<(scene, Vec<Uuid>)>`:
  - sources = the user's vision sources (owned ∪ observer-tier when `observerVision`) that carry a
    `creatures` sense, each with its resolved range — resolved through the SAME
    `token_vision_floors`-class resolver (extended or sibling, never a third precedence walk);
  - source must be grounded (elevation 0 — Task 4's field);
  - targets = tokens in the same scene, grounded, within range (2D center distance);
  - **READ-gated** through `SceneEcs::ctx_access` (`cap::READ`), the same authority the footprints
    channel uses — a permission-hidden token is never named;
  - exclude targets already visible (center cell in the recipient's `player_lit_mask` set for that
    scene) — the channel carries ONLY what the mask doesn't already show.
- Wire: masked `vision` payload gains `perceived: [{ scene, tokens: [uuid] }]`; GM `mode:"all"`
  carries none. ts-rs + Zod + client `toVisibility` parse (fail-closed: garbled `perceived` ⇒
  empty list, never a widened render).
- Tests (`scene/tests/` + `ws/conn` derived-channel tests): through-wall in-darkness perception;
  flying target immune; out-of-range; permission-hidden target never named; already-visible token
  not restated; observer-vision source contributes; see-as target gets the target's set.

## Task 3 — `perceived` client render

- `RenderEngine` parses and holds the perceived set per scene; perceived tokens render THROUGH fog
  via a dedicated overlay pass above `CORE_LAYERS.mask` (the token's `TokenView` is the single
  render object — investigate whether raising the container vs a duplicate marker is cleaner; the
  invariant is: no duplicate visible copies, and unperceiving removes the reveal immediately).
- Fog itself is untouched (terrain stays hidden); explored accumulation untouched.
- Tests: engine parse + reveal/unreveal transitions; sweep interplay (a `visionSweeps` frame does
  not drop the perceived set).

## Task 4 — Elevation fields (server + client mirrors)

- `TokenEngine.elevation: Option<f64>` (None = 0); `LightEngine.elevation: Option<f64>` (None = 0;
  carried emissions use their token's elevation); `WallEngine.elevation: Option<WallElevation>`,
  `WallElevation { bottom: Option<f64>, top: Option<f64> }` (absent end = unbounded; absent wall
  field = blocks every elevation — today's behavior).
- Fail-closed: `bottom > top` ⇒ the wall blocks everything (treated as `{−∞,+∞}`); token/light
  non-finite is unreachable through JSON but the readers clamp to 0 on any non-finite stored value
  anyway (defense in depth, matching the engine-band readers' posture).
- ts-rs + Zod + builders (`buildLightDoc` from M17a, wall builder in scene-tools) + round-trip
  tests.

## Task 5 — Elevation-aware occlusion (server)

- Rule (spec D4): a wall occludes a source at elevation `e` iff `bottom ≤ e ≤ top`
  (absent end unbounded). **Environment ambient is the exception**: `env_light_polys` keeps the
  full `light_walls` set — walls shadow sky-light at every elevation (interiors stay dark).
- ONE filtered accessor pair, no forks: `sight_walls_for(scene, elevation)` /
  `light_walls_for(scene, elevation)`; the bare `sight_walls`/`light_walls` accessors remain only
  where elevation genuinely doesn't apply (env light) with a doc comment saying so. Grep every
  consumer: `player_vision_polygons`, `player_lit_mask`'s `source_los_poly`, `visible_cells` /
  `visible_cells_cached` (the `VisibilityInputsSnapshot` source entries gain elevation so the
  cache can't serve a stale mask), `lighting_inputs_from` per light, move-stream
  `player_vision_inputs` (moving token's elevation), the `Create` placement gate's mask path.
- Tests: see-over (viewer above wall top), see-under (below bottom), blocked inside the band,
  malformed interval fails closed, env light still fully occluded, elevation in the cache snapshot
  (same walls, two elevations ⇒ distinct masks).
