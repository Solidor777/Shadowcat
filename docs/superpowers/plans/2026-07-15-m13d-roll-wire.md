**Goal:** Stat rolls reach chat: a per-stat roll template resolves (via `@shadowcat/formula`'s notation-template mode + the M13b resolver) into pure M11 dice notation posted as an inline-roll chat message — spec §7 (`docs/superpowers/specs/2026-07-15-m13-nightfox-system-design.md`).

**Architecture:** A pure builder in the Nightfox repo (`"nightfox"` package) produces the message *content string* (`<template> [[<notation>]]` — the unresolved template as visible text + one inline `[[…]]` roll embed the server executes at ingest); callers (M13c sheet buttons later; tests now) send it through the existing chat seam. **Zero new wire frames, zero server change** — the M11d-2 ingest caps/entropy/validation remain the security boundary. The differential proof is an end-to-end test against the real Rust server: a built roll that the server rejects is a test failure.

**Tech Stack:** TypeScript, Vitest (unit tests, plus a standalone node↔Rust e2e script mirroring the M13-1 Task 19/20 spawn/parse harness contract), existing `WsClient.sendChatMessage`.

## Global Constraints

- No new dependencies, no server code changes, no ts-rs changes (M13-1 Tasks 19/20 already made the harness-side server/repo changes this plan depends on; this plan itself adds none).
- The builder emits exactly ONE inline `[[…]]` embed per message (server cap `MAX_INLINE_ROLLS = 8`; content ≤ `MAX_MESSAGE_CHARS = 4096` holds by construction: template ≤ 512 + bounded notation).
- Rollable stat types: `number` and `resource` only (spec D7); `text`/`boolean` rolls are `type` errors. Any errored referenced stat blocks the roll (spec §7) — the builder returns the error; it never posts.
- Commit per task once green (inside the Nightfox repo, except Task 3's Shadowcat-repo doc rows).

```ts
/** Builds the chat content for rolling `key` on a resolved doc:
 * "<template> [[<notation>]]". Default template (no `roll` authored) = the bare
 * stat key (a flat-value roll). Returns the FormulaError instead when the stat
 * is missing, unrollable (text/boolean), or any reference is errored. */
export function buildStatRollContent(
  resolved: Map<string, ResolvedStat>,
  block: NightfoxBlock,
  key: string,
): { content: string } | FormulaError;
```

```ts
import { describe, expect, it } from "vitest";
import { resolveNightfox } from "./resolve";
import { parseNightfox } from "./nightfox-docs";
import { buildStatRollContent } from "./roll";

const system = {
  stats: {
    dex: { type: "number", order: 0, base: 3, roll: "d20 + dex" },
    str: { type: "number", order: 1, base: 4 },                       // no roll template
    hp: { type: "resource", order: 2, current: 7, maxBase: 10, roll: "hp.max - hp" },
    neg: { type: "number", order: 3, base: -2, roll: "d20 + neg" },
    frac: { type: "number", order: 4, base: 0, formula: "7 / 2", roll: "d20 + frac" },
    ghostly: { type: "number", order: 5, base: 0, formula: "ghost", roll: "d20 + ghostly" },
    class: { type: "text", order: 6, value: "bard" },
  },
  mechanics: { version: 1 },
};
const host = { id: "A", doc_type: "actor", system, embedded: {} } as never;
const setup = () => {
  const r = resolveNightfox(host);
  return { resolved: r.byDoc.get("A")!, block: parseNightfox(host)! };
};

describe("buildStatRollContent", () => {
  it("resolves an authored template into template-text + one inline embed", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "dex"))
      .toEqual({ content: "d20 + dex [[1d20 + 3[dex]]]" });
  });
  it("defaults to a flat-value roll when no template is authored", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "str")).toEqual({ content: "str [[4[str]]]" });
  });
  it("resource templates: bare = current, .max = final max", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "hp"))
      .toEqual({ content: "hp.max - hp [[10[hp.max] - 7[hp]]]" });
  });
  it("negative values use the parenthesized zero-minus form", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "neg")).toEqual({ content: "d20 + neg [[1d20 + (0 - 2)]]" });
  });
  it("non-integer stat values are a type error (explicit rounding required)", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "frac")).toMatchObject({ error: "type" });
  });
  it("an errored stat blocks the roll", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "ghostly")).toMatchObject({ error: "unknown-ref" });
  });
  it("text/boolean stats and unknown keys are not rollable", () => {
    const { resolved, block } = setup();
    expect(buildStatRollContent(resolved, block, "class")).toMatchObject({ error: "type" });
    expect(buildStatRollContent(resolved, block, "nope")).toMatchObject({ error: "unknown-ref" });
  });
});
```

Note the `1d20` expectation: the M13a template mode normalizes a count-less `d` to `1d` (the server parser requires a count before `d`); the visible template text keeps the user's authored `d20`. The builder itself never rewrites notation — normalization lives solely in `resolveNotationTemplate`.
