# M24 — VFX — Design Spec

> Master: `2026-09-11-phase3-master-integration-design.md` (§2.3 the seam this milestone
> owns; §9 D10). Goal: animated effects on the stage — per-token emitters (`VfxEmission`,
> M18's component model, unplayed until now), transient one-shots any user may fire at a
> point (a fireball, a heal burst), and concurrent playback of many at once without the
> stage stalling. Sound pairing goes through M23's `playOneShot` in the integration task.

## 1. Assets (no new codec — D10)

Two effect formats, both already storable by M15a's pipeline, and BOTH reach the client as
the ONE animated source the render package already loads — `ResolvedAnimatedSource`'s
`{type:"sheet", url, rows, cols, count}` grid (`PixiBackend.loadAnimatedTextures`). No
client-side decoder is added: the client has no path today from a single animated-WebP file
to frames (the `frames`/`sheet` variants are the only two, and Firefox has no `ImageDecoder`),
so frame extraction is the SERVER's job (invariant 6: computation runs on the server).

- **Animated WebP** (stored pass-through today): the asset pipeline (`data::asset::process`,
  which already decodes WebP through the `image` crate) gains a derived grid sheet for any
  animated image: `Variant::Sheet` → `<uuid>.sheet.webp` (frames tiled in a near-square
  `rows × cols` grid, longest side capped at 4096 px — frames downscaled uniformly when the
  grid would exceed it) plus `<uuid>.sheet.json` (`{ rows, cols, count, frameMs: number[],
  width, height }`; per-frame timings from the file), both appended to `SIBLING_SUFFIXES`;
  produced at commit time, no lazy regeneration (the M23 audio rule), `reconvert` retries.
  `ResolvedAnimatedSource.sheet` gains an optional `frameMs?: number[]` (uniform default when
  absent — the existing token-face callers are untouched). Token animated faces may adopt the
  same derivative later; M24 does not change them.
- **Spritesheet**: a PNG/WebP atlas + a sidecar JSON in PixiJS's spritesheet format (`frames`,
  `animations`, `meta`), uploaded as two assets (the JSON pass-through as
  `application/json`), paired by the explicit tag `vfx:sheet=<json-asset-id>` on the IMAGE
  asset (M15a explicit tags; written by the asset browser's "Pair sheet" action and readable
  from the image asset's own metadata — never queried by prefix). The pipeline validates the
  sidecar's `meta.image` names the paired image at pairing time.

**Marking effects.** Every effect asset (either format) carries the constant explicit tag
`vfx` — the server's `tags` filter is exact-match, ANDed, so a constant literal is the only
tag shape a filter can select. The asset browser's "VFX" chip = `kind=image` + `tags=vfx`;
`ctx.pickAsset({ kind: "image", tags: ["vfx"] })` (the pick options gain `tags`, forwarded to
the existing query parameter). The EmissionEditor's VFX section and the FX tool use that
filter. An animated WebP without the `vfx` tag is still a valid emitter asset (the tag is a
browsing aid, never a gate).

## 2. Server

### 2.1 One-shot frames (`ws::protocol`, appended; ScenePing template, all touch points)

```rust
ClientMsg::PlayVfx { scene: Uuid, asset: String, x: f64, y: f64, scale: Option<f64>,
                     rotation: Option<f64>, duration_ms: Option<u32>, sound: Option<String>,
                     elevation: Option<f64> }
ServerMsg::Vfx     { scene: Uuid, user: Uuid, asset: String, x, y, scale, rotation, duration_ms,
                     sound, elevation, id: Uuid }
```

- Handler: per-user rate bucket (separate from ping/emote), scene must exist and be readable
  by the sender, `x`/`y` finite and inside `MAX_GATE_WALK_COORD`-bounded magnitude (the ONE
  admissibility bound), `scale ∈ (0, 8]`, `duration_ms ≤ 60_000`, asset id non-empty ≤ 128
  chars, `sound` likewise. Authz: any world member with `WorldRole::Gm` or `Player`
  (spectators refused) — a one-shot is a table gesture like a ping. `broadcast_aux` to the
  room; no secrecy stake: the client draws it only on the viewed scene, and VFX get their
  OWN layer (§3.1) placed BELOW `mask` in `CORE_LAYERS`, so the fog mask hides an effect at
  a point the recipient cannot see (invariant 11 accepts the frame reaching them).
- `elevation` is carried verbatim; M25's integration makes the layer filter by level.

### 2.2 Emitter playback needs no server change

`EffectiveActor.vfx` already resolves per token (M18); egress already filters by readability.

## 3. Client

### 3.1 Render — `src/client/render/src/vfx-view.ts` + backend seam

- New core layer `"vfx"` inserted into `CORE_LAYERS` between `"templates"` and `"lighting"`
  (so lighting tints effects and the mask hides them; `LayerRegistry` order indices shift —
  `layers.test.ts` pins the new order).
- `DisplayBackend` (append): `setVfx(id: string, spec: VfxNodeSpec)`, `removeVfx(id)`,
  `tickVfx(dtMs)`; `MockBackend` records. `VfxNodeSpec = { layer: "vfx", x, y, scale,
  rotation, source: ResolvedAnimatedSource | ResolvedSheetSource, loop: boolean, anchor:
  VfxAnchor | "point", token?: string, tint?: number }`, where `ResolvedSheetSource = { kind:
  "sheet", imageUrl, sheetUrl, animation: string }`.
- `PixiBackend`: an `AnimatedSprite` per node; sheet sources load through `Assets.load` of
  the sidecar JSON with the image URL rewritten to the asset serve URL (the resolver never
  runs in the backend — `VfxView` pre-resolves both URLs, the backend only loads). Frame
  advance is driven by `tickVfx` (like `tickTokenAnimations`, so `PerformanceSettings.fpsCap`
  and `reducedMotion` govern it: reduced motion plays the LAST frame only for looping
  emitters and skips one-shots entirely). A node whose `loop` is false removes itself on
  `onComplete` (the backend calls the view's `onDone(id)`).
- `VfxView` (the `PingView`/`EmoteView` pattern, pure state + reconcile):
  - **Emitters**: reconciles every readable token in the viewed scene whose
    `EffectiveActor.vfx` is `enabled`; node id `emitter:<token>`; position tracks the token's
    tweened transform each tick through `TokenAnimator.get(id)` (the same transform the token
    node uses — never a second interpolation). **Anchor rule, all three `VfxAnchor` members,
    all inside the `vfx` layer (which sits above `tokens`, so no effect ever draws under token
    art):** `below` = centred on the token's footprint base (its bottom edge), `zIndex` 0;
    `token` = centred on the token's centre, `zIndex` 1; `above` = centred on the token's top
    edge, `zIndex` 2. The M18 doc comments on `VfxAnchor` are rewritten to state these
    placements (today they say only "on/above/below the token's art").
  - **One-shots**: `play(req: VfxPlayRequest & { id })` from the `ServerMsg::Vfx` handler;
    node id `oneshot:<id>`; `duration_ms` caps a looping asset; removed on done. Concurrency
    cap 64 live one-shots per scene (oldest evicted) so a spam burst cannot stall the stage.
  - `PerformanceSettings.vfx == false` ⇒ `reconcile` removes every node and `play` is a
    no-op (read each call, never cached).
- `RenderEngine`: constructs `VfxView` beside `EmoteView`; ONE call site in the store-subscribe
  reconcile block (`vfxView.reconcile()`), one in the ticker (`backend.tickVfx(dt)` +
  `vfxView.tick(dt)`), and `RenderEngine.playVfx(req)` forwarding to the view (master §3
  edit convention). `RenderEngineOpts.vfxAssets?: (id) => ResolvedVfxSource | null` — the
  host resolves the sheet pairing (tag lookup) through `@shadowcat/core`'s asset metadata,
  the render package stays resolver-free for sheets exactly as for token art.

### 3.2 Core + shell

- `@shadowcat/core` `src/client/core/src/vfx.ts`: `VfxPlayRequest` (master §2.3 plus
  `elevation?`), `resolveVfxSource(meta: AssetMeta, resolver): ResolvedVfxSource | null`
  (the server-derived grid sheet when the asset row says one exists — the asset metadata
  gains a `sheet: { rows, cols, count, frameMs } | null` field the server fills from the
  sidecar; a PixiJS sheet when the `vfx:sheet=` tag is present and the sidecar id resolves;
  fail closed to `null`).
- `WsClient`: `PlayVfx` send + `Vfx` handler (Zod member — every field declared);
  `WorldSession.playVfx`/`onVfx` with the `viewedSceneId` cross-scene guard (the emote
  precedent); `AppContext.vfx: { play(req): void; onVfx(cb): () => void }`.
- `Stage.svelte`: `engine.playVfx` on `onVfx`; passes `vfxAssets`.

### 3.3 UI — `src/modules/vfx/` (`@shadowcat/module-vfx`)

- **Scene-tools "FX" tool** (contributed into the rail like the emote palette — the module
  contributes a `scene-tools` tool contract entry; if the rail has no such extension contract
  today, ADD one: `SCENE_TOOL_CONTRACT` with `{ id, icon, labelKey, onSceneClick(x, y) }`,
  which is the render-layer-API-style seam ARCHITECTURE §2 invariant 7 asks for and lets
  external modules add tools): pick an effect asset (`ctx.pickAsset` with the VFX filter),
  scale, optional paired sound (`pickAsset({kind:"audio"})` — M23 seam; before M23 merges the
  picker shows every asset), then click the stage → `ctx.vfx.play`. Available to players
  (server authz decides).
- **Emitter authoring** already exists (`EmissionEditor`, M18/M20); its VFX section gains the
  VFX asset filter and a live preview thumbnail.
- **Chat**: `/fx <asset-id-or-name> [@token]` is intercepted in `handle_send_message` BEFORE
  `parse_command` runs (the `/roll` failure-notice precedent: `parse_command` stays a pure
  three-kind classifier and `MessageKind::System` stays unreachable from any parse path);
  the server resolves the token centre (never the client), reuses the `PlayVfx` handler's
  validation + authz, broadcasts `Vfx`, and answers the sender with the existing whispered
  notice mechanism (`build_roll_error_notice`'s shape) on failure — no message document is
  created for a successful `/fx`.

## 4. Sound pairing (integration task, after M23 merges)

`ServerMsg::Vfx.sound` ⇒ the shell calls `ctx.audio.playOneShot(sound, { channel: "sfx" })`
in the same `onVfx` handler, gain from the emitter's `volume` when the source is an emitter
(a `VfxEmission` has no sound field; the pairing is the token's `SoundEmission`, played by
M23b's audibility path — so emitters need nothing here; only one-shots pair).

## 5. Tests

- Server: handler authz (spectator refused), bounds (each cap), rate bucket, `/fx` resolves
  the token center server-side and refuses an unreadable token.
- Render: `layers.test.ts` new order; `vfx-view.test.ts` — emitter appears/disappears with
  `enabled`, tracks a tween, `Below`/`Above` ordering, one-shot removed on done, 64-cap
  eviction, `vfx:false` removes all and ignores `play`, reduced motion (last frame / skipped);
  `pixi-backend.test.ts` (mock GL) — sheet URL rewrite, `tickVfx` advances, `onComplete`
  calls `onDone`; `engine.test.ts` — one reconcile call site.
- Core: `resolveVfxSource` truth table (`// @vitest-environment node`): derived sheet
  present ⇒ `sheet` with `frameMs`; `vfx:sheet=` tag ⇒ PixiJS sheet; neither ⇒ `null`.
- Server pipeline: an animated WebP synthesized in the test (3 frames, distinct timings) ⇒
  `.sheet.webp` + `.sheet.json` with `count: 3` and the timings; a still image ⇒ no sheet;
  a > 4096 px grid ⇒ uniform downscale; `reconvert` regenerates; export/import carries both.
- Module: FX tool posts `play` with the picked asset; contract registration.
- e2e `vfx.spec.ts` (written here, dispatcher-run): GM uploads an animated WebP fixture
  (generated in the test from a 2-frame image via the pipeline? No — commit a 2-frame 8×8
  animated WebP under `e2e/fixtures/` — a tiny synthetic file, no third-party art), places it
  as a token's VFX emission → `data-vfx-count="1"` on the stage for both GM and player; FX tool
  click → `2` on both; player toggles `vfx` off → `0` on the player only.
